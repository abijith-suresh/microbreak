# Microbreak — agent brief

Short, non-addictive puzzle games for the micro-wait moments of software development, for developers and other knowledge workers.

## The Project

Core promise: a curated set of short (~2–8 min), brain-stimulating puzzle games that load instantly, need no accounts or setup, and end cleanly instead of holding attention.

Goals: give developers something better than mindless scrolling during build/test/deploy waits; be personally useful to the builder; work equally well on desktop and mobile; stand as a quality portfolio piece.

Non-goals: monetization or ads; user accounts, auth, or server-side state; analytics or any data collection; engagement mechanics (streaks, notifications, leaderboards, daily limits); long-form or deeply complex games; virality or mass-market scale; being a general-purpose game platform.

Constraints (hard): free forever; fully client-side static site with no backend and no external APIs (self-hosted fonts only); responsive and touch-friendly; offline-capable once loaded.

Game selection: short session (under ~10 min, ideally 2–8), brain-stimulating (thinking over reflex or luck), properly implemented. Curation is by discretion; there is no fixed catalogue ceiling.

Success: the builder uses it during real development waits; a small number of fellow developers get value from it; it beats the alternative of mindless scrolling.

Status: live.

## How I Work Here

- Quality gate: `bun run verify` — run before handoff.
- Commits: Conventional Commits; types live in `commitlint.config.ts`. Squash merges; never commit to main.
- E2E is not part of `verify`. Browser tests run separately via `bun run test:e2e:build`, which needs Playwright browsers installed once.
- Follow the layered game architecture for any new game: pure engine (`src/lib/<game>.ts`) → SolidJS composable (`src/lib/<game>Game.ts`) → session validator (`src/lib/<game>Session.ts`) → app component (`src/components/<Game>App.tsx`) → Astro page (`src/pages/<game>.astro`).
- Reuse the shared components (`GameScreen`, `ResultScreen`, `BackLink`, `Button`) rather than adding new ones.
- All localStorage access goes through `src/lib/storage.ts`; keys live in `src/lib/storageKeys.ts` and are versioned (`<game>Session:v1`). Invalid restored sessions are silently discarded.
- Product constraints above are invariants: no server runtime, no external APIs, no analytics or tracking.
- `CHANGELOG.md` is generated by release-please. Never edit it manually.
- Git hooks: pre-commit runs lint-staged (Biome), commit-msg runs commitlint, pre-push runs the full verify.
- Styling is Tailwind CSS v4 via the Vite plugin (not PostCSS), with design tokens and light/dark themes defined in `src/styles/global.css`.

## Getting Around

- `src/components/` — SolidJS `.tsx` and Astro `.astro` UI; shared primitives in `ui/`, home-page previews in `previews/`
- `src/data/` — static data: game catalog (`games.ts`), preview grid config, Wordle word lists
- `src/layouts/BaseLayout.astro` — root HTML shell (fonts, meta, theme init, SEO)
- `src/lib/` — pure game engines (`<game>.ts`), SolidJS composables (`<game>Game.ts`), session validators, `storage.ts` / `storageKeys.ts`; unit tests in `__tests__/`
- `src/pages/` — Astro file-based routes: home, about, 404, and one page per game
- `src/styles/global.css` — Tailwind setup, design tokens, light/dark themes, animations
- `tests/e2e/` — Playwright browser tests; `public/` — favicon, OG image, self-hosted fonts
- `CONTRIBUTING.md` — setup, scripts, quality gate, adding a new game; `README.md` — product overview and architecture
